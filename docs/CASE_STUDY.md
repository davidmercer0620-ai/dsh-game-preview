# 实测案例：一间两个人的工作室，用 AI 做小游戏

这份文档只记录**能复现的数字**，全部来自 `F:\炉石传说`（Cocos Creator 3.8 自走棋）和 `F:\降维联盟`（ES module + Canvas）两个真实工程。

## 1. 原生窗口捕获

| 项目 | 数值 |
|---|---|
| Unity 编辑器窗口 | 1920×1030，**15.2 fps**，单帧 JPEG 约 107 KB |
| 画质档「流畅」(1100 px) | **23.8 fps** |
| 首帧延迟（attach → 第一帧） | 11–435 ms |
| 抓帧长轮询 | 首帧 3.9 ms，后续 5.3 ms，空闲 204（1.5 s 后） |

> 为什么不是 60 fps：`PrintWindow` 每次要整窗重绘，15 fps 已经足够看清 UI；输入是即时转发的，操作手感不受抓帧率影响。

## 2. 封包（APK）

```
$ Postman Game Studio / dsh-game-preview  →  📦 导出 · Android APK
BUILD SUCCESSFUL in 1m 20s
完成：F:\造化万物3\dist\apk-2026-11-08T17-44-28.apk（6.5 MB）
```

- 构建方式：复用工程自带的 `android/build.sh`（Gradle 8.14.3 / JDK 17 / SDK）
- 打包耗时：**1 分 20 秒**（39 个 task，24 executed / 15 cached）
- 产物校验：文件头 `50 4b 03 04`（标准 APK）

## 3. 包体积

| 平台 | 提交物 | 体积 | 上限占比 |
|---|---|---|---|
| 微信小游戏 | 目录 | 2.24 MB | 55.9% |
| 抖音小游戏 | 目录 | 2.21 MB | 55.3% |
| TapTap | `game.zip` | **0.64 MB** | 16.0% |
| web-desktop | 目录 | 2.20 MB | 6.9% |
| web-mobile | 目录 | 5.37 MB | 16.8% |

> 一开始我把 TapTap 的「源目录 + 提交 zip」重复累加，得出 80.9% 的假警报。**商店限制只针对提交物**，修了统计口径后是 16%。这类错误自己不算一遍是发现不了的。

## 4. 引擎裁剪

扫描 7 个场景、25 个脚本后的结论：

```
看到：cc.Vec4×42 · Graphics×31 · cc.Camera×7 · cc.Canvas×7 · cc.UITransform×7
引擎包：3.96 MB
未使用：Physics 2D/3D · Spine · DragonBones · TiledMap · VideoPlayer · WebView
        Particle 3D · Skeletal · 3D Mesh · Lighting · Terrain · Audio
```

纯 `Graphics` 绘制的 2D 项目，**14 个重型模块一个都用不到**。Cocos 的功能裁剪通常能把这 3.96 MB 砍到 1.5–2 MB。

## 5. 运行时健康（探针）

静态服务在返回 HTML 时注入 `/probe.js`，页面自己上报：

```
fps: 60 · errors: 0 · 资源 404: 0
```

这一条来自 `炉石传说` 的 web-mobile 构建。它的价值在**出错时**：`TypeError: xxx is not a function at assets/main/index.js:1:234` 会直接出现在面板和 agent 的工具结果里，而不是"游戏黑屏了"。

## 6. 一键验收

```
结论: warn
fps: 60 · 错误: 0
原因: 引擎还有 14 个未使用模块可裁剪（预计省 0.5–1.5 MB）
体积: wechat 2.24MB(55.9%) · douyin 2.21MB(55.3%) · taptap 0.64MB(16%)
```

`warn` 是准确的：页面零错误、帧率正常、包在预算内，但引擎还有明显可省的空间。

## 7. 视觉对比

同一场景连续两帧（静止界面）：

```
像素变化 0.1%   ← 噪声量级，说明对比够灵敏
```

UI 被改坏时这个数会是几十个百分点。

## 8. 时间线

45 秒录制（画面变化门控，最少间隔 4 秒）：

```
12 帧，每帧约 54 KB → 合计 640 KB
```

十分钟的 agent 工作 ≈ 十几张关键静帧，而不是一段视频。

---

## 这些数字说明了什么

1. **不需要 60 fps** 才能看清一个编辑器；15 fps + 即时输入就够。
2. **打包的价值不在快，在不用切窗口**：一条命令从"改完代码"到"6.5 MB 的 APK"。
3. **体积统计口径比工具本身更容易错**——所以才要写进面板，并带上"源目录 vs 提交包"的区分。
4. **真正救命的不是画面，是报错**：agent 改完代码后游戏黑屏，探针能给它一行堆栈。
