# FAQ

## 这和 MCP 服务器有什么区别？

UnityMCP、openclaw 这类项目解决的是**让 agent 能操作编辑器**（建场景、改组件、跑构建）。这个插件不碰那一层，它解决另一半：

| | MCP 类项目 | dsh-game-preview |
|---|---|---|
| agent 能不能改游戏 | ✅ | ❌（不重复造） |
| 人能不能看见游戏 | 部分 | ✅（侧栏内、可操作） |
| agent 能不能**看见**运行时错误 | ❌ | ✅（探针注入） |
| 改完到底还能不能玩 | ❌ | ✅（回放 + 像素对比 + 一键验收） |

一句话：**它们让 agent 动手，我们让 agent 验收。**

## 一个"看编辑器"的插件，对 AI 工作流有什么用？

这是最有价值的质疑。答案在我们的早期版本里是"没用"——如果只是把编辑器画面录进侧栏，双屏开发确实不需要它。

现在它做的是**结果监控**，不是直播：

- 画面只在真正变化时记一帧（变化门控 + 8 秒下限），十分钟的 agent 工作变成几张静帧
- 收工后看时间线 + 一键 GIF，回答"它到底改了哪几个阶段"
- 报错从页面直接回传，agent 不用靠猜

## 支持 macOS / Linux 吗？

**不支持原生窗口捕获**（`PrintWindow` 是 Windows API）。但：

- web 预览（dev server / 导出包 / 探针 / 回放 / 对比 / 体积 / 打包脚本）在 macOS 上是纯 Node + HTTP，理论可移植
- 目前只在 Windows 10/11 上验证过，README 里明确写了这一点

如果你要 macOS，请开 issue 说明你用的是哪个引擎、什么工作流——我会按需求决定先做哪个。

## 为什么面板要走 iframe 桥，而不是直接 fetch？

DSH 桌面版页面运行在 `dsh-app://app/`，preload 会拦截发往回环地址的 `fetch`/`XMLHttpRequest`，失败是**静默的**（不报错、没响应）。实测只有两个通道能通：

1. 一个隐藏的同源 iframe（`/bridge`）+ `postMessage`
2. `<img>` / iframe 这类不经过 fetch 的加载

所以插件的传输是按 `bridge → XHR → fetch` 顺序探测的，桥断了会重建（宿主重启后也自动恢复）。

## 会不会很吃性能？

- 抓帧是**按需**的：只有你在看预览时才跑，关掉即停
- 时间线默认开着，但只是对已经到达的 JPEG 做一次 SHA1，且 8 秒下限——空闲编辑器一帧都不存
- 探针每 2 秒上报一次 FPS，一个 `sendBeacon`

## 为什么还要一个「手机视口」？

小游戏的分辨率、触控区、UI 安全区在 PC 上根本看不出来。面板给的是**真的** 390×844 逻辑视口，而不是缩放一个矩形：

```
web-mobile 构建（竖屏 720×1280 · 自适应） → 手机档 390×844
web-desktop 构建（固定画布）              → PC 档 1280×720
```

装错构建时面板会直接说"这个包是 PC 构建，手机预览会溢出"。

## 我的项目不在支持列表里怎么办？

检测顺序是：Cocos / Godot / Unity / 微信开发者工具 / dev server / 静态文件 / 构建产物 / 手动 URL。都没有时给你一个 URL 输入框——任何能在窗口里跑起来的东西都能接。

## 装了没反应？

三种最常见的原因：

1. **右侧栏被关了** —— 点聊天头部的 `▷ 预览` 按钮（或右上角侧栏开关）
2. **页面还是旧客户端** —— DSH 桌面版没有绑定刷新快捷键，必须完全退出重启
3. **Windows 版本太低** —— `PrintWindow` 的 `PW_RENDERFULLCONTENT` 需要 Windows 10 1803+

面板进度条右侧会显示客户端版本号（如 `v0.13.3`），看到新号就说明页面已是新版。
