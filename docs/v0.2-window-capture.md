# v0.2 设计：原生窗口捕获（Godot / Unity）

> 目标：让「编辑器里按 Play 跑起来的原生窗口」出现在右侧栏，而不只是一个 Web iframe。
> 这是 v0.1 明确推迟的部分；本文只定方案与验收，不含实现。

## 1. 为什么值得做

你的两个 Steam 主力引擎（Godot / Unity）的**最快回路是原生运行**，不是 Web 导出：

| 引擎 | 最快回路 | 耗时 | 走 v0.1 的 Web 路线 |
|---|---|---|---|
| Cocos | 编辑器浏览器预览 | ~1s | ✅ 已经是 v0.1 |
| Godot | 编辑器 F5 → 原生窗口 | ~2s | 导出 HTML5 要 5–15s，且行为不一致 |
| Unity | 编辑器 Play | ~3s | WebGL 构建 1–30 分钟，不可用 |

所以 v0.2 补的不是"锦上添花"，是把 Godot / Unity 从"仅识别"变成"能用"。

## 2. 抓帧：三条路线与选择

| 方案 | API | 帧率 | 兼容性 | 结论 |
|---|---|---|---|---|
| `BitBlt` / `PrintWindow` | GDI | 5–10 fps | 最广，但 D3D 独占常黑屏 | **降级兜底** |
| Windows.Graphics.Capture | WinRT | 30–60 fps | Win10 1903+，能抓大多数窗口 | **默认** |
| DXGI Desktop Duplication | DXGI | 60 fps | 抓整屏，需处理遮挡 | 不用（不是按窗口） |

选型：**WGC 优先，黑帧自动降级 PrintWindow，再黑就报错并给建议**。

降级的判定不能靠"猜"：同一窗口连续 3 帧全黑（或 alpha 全 0）才降级，避免误判深色场景。

## 3. 实现形态：一个常驻 PowerShell 助手

Node 直接调 WinRT 很别扭（需要 `winrt` 绑定或 C++ 插件）。用 **PowerShell 5.1 常驻子进程**，P/Invoke + `Windows.Graphics.Capture` 互操作，把帧以 base64 行协议吐到 stdout：

```
stdout:  DATA <base64-jpeg> <width> <height> <frameNo>
stdout:  ERR  <code> <message>
stdin :  CAPTURE <hwnd> <fps> <maxWidth>
stdin :  STOP
```

选择它而不是原生 addon 的理由：零编译、零依赖、Windows 自带、出问题能单独跑脚本调试。
代价：单帧走 stdout 有拷贝开销，所以限制 `maxWidth ≤ 1600`、JPEG q≈70。

Host 侧新增 `host/window.js`：拉起助手、维护最近一帧、把帧推给 `/stream`。

## 4. 传输与面板

- 端点：`GET /stream`（`multipart/x-mixed-replace; boundary=frame`），`<img src>` 直接吃，和 iframe 二选一。
- 面板：`capture.kind === 'window'` 时舞台渲染 `<img>` 而不是 `<iframe>`，Playtest Bar 的按钮语义不变。
- 无帧时渲染最后一次成功帧 + `已断流 Ns` 角标，不闪白。

## 5. 输入：只转发，不代打

窗口捕获的输入必须显式设限，否则会变成"看起来能用实际不能用":

- **只做人 → 游戏的转发**：面板聚焦时把键盘/鼠标事件用 `SendInput` 打到目标窗口。
- **前提**：`SetForegroundWindow` 成功。失败就提示"点一下游戏窗口再按键"，不静默丢弃。
- **不做 agent 输入**：脚本化输入只走 Web 通道或引擎桥。窗口捕获的 agent 输入写进 README 的"不支持"清单，避免承诺做不到的事。
- **独占全屏不做适配**：检测到全屏且抓不到，直接建议切无边框窗口。这是 DSH 里唯一需要用户改设置的地方，要在 UI 上写清楚。

## 6. 窗口匹配

`launch.cmd` 启动后，按以下顺序锁定窗口：

1. 启动进程的 PID → 遍历顶层窗口取 `GetWindowThreadProcessId` 匹配（最准，适合 Godot `--path` 和 Unity `-projectPath`）
2. 进程树里新出现的窗口（编辑器 Play 模式：窗口属于编辑器 PID）
3. 标题/类名通配（`windowMatch: "Godot*"`），作为手动兜底，面板上给一个"重新选择窗口"的下拉

第 2 条是 Godot/Unity 的关键：Play 窗口往往不是新进程，而是编辑器新建的窗口。

## 7. 失败模式（按优先级处理）

| 现象 | 判定 | 给用户的话 |
|---|---|---|
| 连续全黑帧 | 3 帧 | 「这个窗口用独占全屏，抓不到；切无边框窗口」+ 一键重试 |
| 窗口最小化 | 尺寸 0 | 「最小化时无法捕获，请还原窗口」 |
| 找不到窗口 | 25s | 「没找到游戏窗口：确认已启动，或用『重新选择窗口』」 |
| 帧率 < 5 | 滑动窗口 2s | 角标显示黄灯，附「降低分辨率」开关 |
| 助手进程崩溃 | exit | 自动重启一次，再失败则回退到 PrintWindow 并标注 |

## 8. 验收标准

- [ ] Godot 4.x 编辑器 F5 起的窗口，2 秒内出画面，稳定 ≥ 25 fps（1600px 宽）
- [ ] Unity 2022 LTS 编辑器 Play 窗口同上
- [ ] 关闭游戏窗口后，面板 3 秒内显示"画面已断开"而不是冻结在最后一帧
- [ ] `⏹ 停止` 关掉游戏进程（`taskkill /T`），不留孤儿
- [ ] 独占全屏时给出可执行建议，不出现纯黑无提示
- [ ] 面板宽度拖拽时帧率不下降（不重建流）

## 9. 工作量拆分（三个 PR）

1. **PR1 抓帧**：`host/window.js` + PowerShell 助手 + `/stream`，面板能看不能玩（可单独发布）
2. **PR2 输入**：键盘/鼠标转发 + 前台校验 + 失败提示
3. **PR3 生命周期**：窗口匹配、断流检测、崩溃重启、降级与文案

## 10. 仍然不做

- 引擎桥（Godot TCP 6007 / Unity Editor 连接）——那是 v0.3，能读实体状态时才值得
- 录制回放——需要先有稳定的帧源
- macOS / Linux 的窗口捕获（WGC 是 Windows 专有；Linux 走 X11 SHM，macOS 走 ScreenCaptureKit，各是独立工作量）
